Workload `wl-mv61aqy1u13zls` (normal stakes, plan revision 3 at `~/agent-scratch/agent-system-2.0/wl-mv61aqy1u13zls/PLAN.md`, approved by Jo). **The problem:** prose instructions to a model drift; code that renders, gates, refuses or tests does not. Jo's rule (ledger input `in-mv61a9s52y4g00`, restated as `in-mv61awnt8uhxxc`): *"anything as2 has to do is done by code that renders, gates, refuses or tests it, and a prose instruction to a model is the fallback only where code cannot reach"*. Its scope (Jo, `in-mv61vrgz48tpts`): work done on or with as2 or any other agent, LLM or AI software, meaning as2's lanes, hands, gates, surface and classifier; Plumb, Tinker and the other seats; skills, tier files, prompts and briefs; and any LLM or AI feature in a product repo. The check fires on every as2 plan and slice, with no AI marker (Jo, `in-mv61vrk3ca8q2o`, `every-plan`): code cannot reliably tell AI work from other work, and a tag costs any other slice one bracket. SPEC-2.0.md § B14.3 (*Amended 2026-10-13 — machinery first for all work*) widens the P-16 proposal ladder to all of that work: render, gate, refusal and test before prose, and prose only with a stated reason. **The grammar:** each slice line of a plan question becomes `- <slice id>: <what it does, one line> [<enforcement>]`, the tag one or more of `render`, `gate`, `refusal`, `test`, comma-separated, lower case, no repeats, optionally followed by `prose` last; any stated reason, `prose: <reason>`, has at least two words, prose alone is `[prose: <why code cannot reach it>]`, and bare `prose` beside another word passes (`[test, prose]`); the tag counts toward the 160-character line limit. Code checks the form, not whether the named enforcement is real: Jo judges the line, reviewers the diff. **Two refusals, one check** (in `surface/src/launch.ts`): `lane_raise_question` refuses a plan question offering approve whose slice lines lack a well-formed tag and names every offending slice in one refusal (this extends item 42's plan-question shape; SPEC § B6, *Amended 2026-10-13 — enforcement tag*); `lane_add_slice` refuses a `task` without the same tag on every workload, plan-first or not, naming the slice by its `id` or as `the new slice`, before the plan-first gate (Jo, `in-mv61vrgxu5iuio`), so a plan line and the slice row it becomes read alike. Slices machinery writes straight to the ledger (the standing, ceiling and full-suite slices) carry no tag. **Cut-over:** questions already raised and slices already in the ledger are never re-checked (the needs-you render and `approve` read them as before; an untagged ledger slice still takes `lane_complete_slice`, `lane_raise_question` and `slice_artifact`); a re-raise after `revise` needs tags; running lanes keep the check they loaded until relaunched. `tiers/lane.md` carries the scope, the grammar, the five meanings and the rule; the lane's first prompt and both refusals render the text the check is written against.
