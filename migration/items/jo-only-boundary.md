**Built on branch `wl/wl-mv654hoqwpfhmo-auth` (PR-C of workload `wl-mv654hoqwpfhmo`, production stakes, plan revision 14 at `~/agent-scratch/agent-system-2.0/wl-mv654hoqwpfhmo/PLAN.md` § 6, approved by Jo).** Some ledger rows carry Jo's authority: every `instructions` row authored `jo` and written by the surface (answers, withdrawals, mode flips, and the words `stakes:`, `ceiling:`, `rounds`, `stop-reviews`, approve / deny, `cap`, `switch`), and every control prefix only the surface writes (`plan:`, `done:`, `repo:`, `ceiling:`, `launch-requested:`, `lane-model:`, `cap:`, `switch:`, …). Until now a lane or hand could write any of them with the stamp `orchestrator-surface` from eval or a script, and the readers took it as Jo's word. `ledger/src/authority.ts` is now the one table of those rows (`AUTHORITY`, each with the reader that trusts it) and the one predicate the readers use (`joAuthority`: author `jo` and stamp `orchestrator-surface`). Row 11's direct channel (author `jo`, the lane's own stamp) is listed there as Jo's words, not Jo's authority.

**Threat model: accident grade.** In scope is an agent (a lane, a hand, or a process either starts) that by mistake, confusion or a bad instruction writes a row only Jo or the surface may write, or opens the ledger outside its tools. Out of scope: a deliberate same-uid attack that rewrites its env, drops a temp trigger it knows about, or brings its own SQLite build. The orchestrator agent is itself an agent with eval and bash, but its process *is* the surface (role `orchestrator`, no lane or workload id), so layer 1 does not cover it: for the orchestrator process the boundary is layers 2 and 3 only.

**Layer 1, the database.** `Ledger.open` gives a connection per-connection `TEMP` triggers on `main.workloads`, `main.slices`, `main.messages`, `main.questions`, `main.instructions` and `main.entries` (insert and update) when the process is an agent context (`AGENT_SYSTEM_ROLE` set to anything but `orchestrator`, or `AGENT_SYSTEM_LANE_ID` / `AGENT_SYSTEM_WORKLOAD_ID` set) and the file is in a live root (`liveRoots()` in `ledger/src/locality.ts`, now used outside test too; a root set that cannot be read counts as live). The triggers raise `Jo-only boundary: …` on any row stamped `orchestrator-surface` (`created_by`, or `changed_by` on updated tables) and on any `author = 'jo'` instruction that is not row 11's shape (kind `instruction`, channel `direct`, no question). They sit under `ledger.db` and `ledger.write(fn)`, so the raw connection is covered, not only the helper methods. Temp triggers write nothing to the file: no `sqlite_master` row, no schema change. No option removes them; the open option `authority: "enforce"` only adds them, which the boundary's own tests use on a scratch file. Throwaway ledgers outside a live root get no triggers in any process, so tests that write surface-stamped rows, a lane-run chaos on its scratch ledger and seeded proofs keep working; every lane-stamped write (the lane tools, the runner's `lane-runner` rows, row 11) stays allowed on the live file.

**Premise.** This install's ledger is at the default path (`~/.agent-system-2/ledger.db`) or named by `AGENT_SYSTEM_LEDGER_DB` in the lane's environment. Those, with the test preload's `AS2_TEST_*` names, are the only inputs that change the root set, and layer 2 refuses an agent setting them.

**Layer 2, the gate.** P-11 row 10 (`gates/src/rows/r10-raw-ledger.ts`, with detectors in `gates/src/eval-code.ts`) refuses, for every role, with a reason naming the "Jo-only boundary": eval or inline (`bun -e`) code that loads the ledger module (`ledger/src`, by import, dynamic import or require); code that names a `ledger.db` in an open or a write, or loads a database module and names a path under `.agent-system-2/`; `sqlite3` without `-readonly` on a `ledger.db` or under `.agent-system-2/`; and any set, unset or override of `AGENT_SYSTEM_ROLE`, `AGENT_SYSTEM_LANE_ID`, `AGENT_SYSTEM_WORKLOAD_ID`, `AGENT_SYSTEM_LEDGER_DB` or an `AS2_TEST_*` name (a prefix or `env` assignment, `export`, `declare`, `unset`, `env -u`, `env -i`, the bash tool's `env` input; in eval `process.env.X = …`, `delete process.env.X`, `os.environ[…] = …`, `os.environ.pop(…)`, `putenv`). Reading stays allowed: `sqlite3 -readonly <ledger>` with SELECT, `echo $AGENT_SYSTEM_ROLE`, `process.env` reads, and `bun test <file>`.

**Layer 3, integrity commands need Jo at a terminal: merge condition, not built here.** `migrate` (PR #72) and `restore` (PR #74) must refuse unless stdin is a TTY and Jo types the ledger path back; lanes run `omp --mode rpc` with no TTY. Neither script is on `origin/main` at `21699ad` (`ledger/scripts/` holds `backup.ts` and `init.ts` only), so the TTY check and the typed path are a merge condition of #72 and #74: neither merges without them.

**Switch: none — a boundary a lane can switch off is not one; Jo q-mvfl9h64q7ivpc.**

**Known limit.** Four readers still accept an answer authored `jo` without checking the stamp: `classifier/src/lab.ts:388` (`unspentGrant`), `surface/extensions/lane-tools.ts:120` and `:139`, and `surface/src/pair-suggest.ts:244` (line numbers as of this item's commit). Layer 1 refuses an agent's write of such a row to the live ledger, so on this install only the surface can produce one; moving those readers onto `joAuthority` is the remaining step.

**Also refused by layer 1, by design.** `surface/scripts/chaos.ts` and `surface/scripts/scratch-smoke.ts` stamp rows `orchestrator-surface`. They run against scratch ledgers, which sit outside the live roots and get no triggers. Run from a lane against a ledger in a live root, they are refused. `bin/as2` started from a lane's shell inherits the lane's `AGENT_SYSTEM_LANE_ID` / `AGENT_SYSTEM_WORKLOAD_ID`. That process is then an agent context, and its surface writes to the live ledger are refused. Start the orchestrator from Jo's terminal.

Tests: `ledger/test/authority.test.ts` (the table is complete against `WRITERS` and the instruction kinds; the triggers refuse and allow as above; no `sqlite_master` change), `gates/test/authority-gate.test.ts` (every refused form, for lane, hand and orchestrator; the reads that stay allowed), `classifier/test/authority-readers.test.ts` (a lane-stamped `author jo` row never satisfies `ceiling:`, `rounds`, `stop-reviews`, `cap`, `switch` or a question answer).
