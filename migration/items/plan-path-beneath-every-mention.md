**Built on branch `wl/wl-mv61a8dh4aeneo`, PR #112.** Workload `wl-mv61a8dh4aeneo` (normal stakes, plan revision 4 at `~/agent-scratch/agent-system-2.0/wl-mv61a8dh4aeneo/PLAN.md`, approved by Jo). **Why:** item 42 made the first plan ask carry its path, but restatements dropped it: the clean-shell plan ask (#22) and the PR #100 conflict-plan ask (#28) on 2026-10-12/13 named the question with no path. **What:** a machinery fix, not an orchestrator instruction. The path is read from the question row (its body's first line, for an open question its workload holds as the plan question: `openPlanPath` in `surface/src/plan-paths.ts`), never from model text. Surface-written lines (echoes including "which one?", tick notices, the wake render and `orchestrator_ledger`, needs-you lines) get `plan for <ref>: <path>` beneath the naming line, uncut, once per question (`withPlanPaths`, idempotent); the plan question's own body now starts on the line beneath its q- id in `errorLines` and `renderWorkload`, so its path sits directly beneath. The orchestrator's own reply is never edited: a display-only `surface-plan-path` message (`surface/extensions/plan-path.ts`) paints after it when the session is idle, one line per mention in message order, and is dropped from model context (the `context` hook) and from compaction input (`session_before_compact`); P-11 rows 1 and 15 read only assistant messages, so they never see it. **Matching:** `q-…` ids and needs-you `#N` only, never after `PR`, `pull request`, `issue` or `item`, nor in `owner/repo#N`; answered or withdrawn questions and non-plan questions get nothing. **Tradeoff approved by Jo:** a mid-turn message (text before its tool calls) gets its paths when the turn goes idle, below the tool output; the final reply has them directly beneath it. **Limits:** a `sendMessage` that throws keeps the lines queued for the next idle turn, but OMP 18.8.6's `sendMessage` returns `void`, so an asynchronous rejection (reported by OMP itself as an `extension_send` error) loses that message's lines, as it would a wake push; compaction paths that bypass `preparation` are not covered, as in `fence.ts`.
