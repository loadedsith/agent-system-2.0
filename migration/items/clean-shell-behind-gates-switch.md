**Built on branch `wl/wl-mv5lrh0drbg0zk`, PR #113.** Workload `wl-mv5lrh0drbg0zk` (production stakes; plan revision 8 at `~/agent-scratch/agent-system-2.0/wl-mv5lrh0drbg0zk/PLAN.md`: revision 7, approved by Jo, with plan review openai-codex/gpt-6-astra round 6 pass and Kimi unavailable on a 429 balance; revision 8 is Jo's change of approach, `in-mv64ikvmebzls0`, fault tolerance over exhaustive proof). Item 100 waits on this item (Jo, `in-mv5lqte3iylzb4`, "separate"). **Problem.** Item 100's plan relaxes a row-6 refusal only when the shell's initial state is known. OMP 18.8.6 gave no such state: with a bash-named shell it sources a snapshot of the user's rc (functions, and options including allexport); a named call runs in the daemon broker, whose env is whatever started it; `~/.env` and the launch env can carry `BASH_ENV`; and a `pty: true` call can run a login shell. The test-first regression (`gates/test/shell-start-session-*.test.ts`: real `omp` lane, hand and orchestrator sessions on a stub model, five routes each) was red on `2c1162b`. An rc variable reached every embedded route, named calls ran `BASH_ENV`, a `BASH_ENV` from `~/.env` and an exported `BASH_FUNC_` were not refused, and a cached Shell kept a removed name after a `shell.env` value with a newline. **Change (no OMP patch).** New `gates/src/shell-start.ts` `shellStart(host, ctx, input, cwd)` is called by the fence for every call and never cached. It certifies: the pinned host, the fence on and auto-background on; a shell whose basename is not bash-named (`/bin/sh` and `/bin/zsh` load no snapshot); no command prefix; direnv off; not ACP; no `name`; `pty: true` only with `PI_NO_PTY=1` in the process; the C environ (read through `_NSGetEnviron`) equal to its read at gate load; no newline in any `shell.env` value; and no hook name, `BASH_FUNC_` name, non-identifier name or `() {` value in `cert.env` (the C environ ⊕ `shell.env` ⊕ the non-interactive env). **The switch** (`gates/src/clean-shell.ts`) is the installed profile's `gates.cleanShell`. Absent or `"off"` means off everywhere. `"all"` means on everywhere. A list of workload ids means on for those lanes and their hands; the orchestrator is on only under `"all"`. The gates read the file at every bash call (re-read when its stat changes), so a running session follows it on its next call. OMP's own settings watch reloads it only after a 200 ms debounce, so the gates do not rely on it. `as2 clean-shell off|all|<wl-id>` writes it, and `profile/config.yml` ships `"off"`. Where the switch is off, the fence never calls `shellStart` and wraps every call as before this item; `shellStart` returns `certified: false` with a reason naming the switch, which item 100 must treat as uncertified. Where it is on, the fence refuses an uncertified call fail-closed, naming the condition and its fix. An unreadable or malformed value counts as off, and the fence says so once per session. **Global change kept:** `bash.direnv: "off"` (`profile/config.yml`), a stated deviation from off being main: direnv is not installed on this machine, and OMP treats an absent direnv as a no-op. **Launch env, switch-bound:** the launchers drop `SHELL_START_HOOK_NAMES` (BASH_ENV ENV SHELLOPTS BASHOPTS POSIXLY_CORRECT CDPATH PS4) only where the switch is on for that launch: `bin/as2` for the orchestrator under `"all"` (read through `gates/scripts/clean-shell.ts`), and `laneEnv` (`surface/src/launch.ts`) for a lane whose workload it turns on, read from the installed profile at each spawn. Off, unreadable or malformed, nothing is dropped and the launch env is main's. **Removed against revision 7:** the profile's `shellPath: /bin/sh`, and `PI_NO_PTY=1` from both launchers. The tier files say: where the clean shell is on, named calls are refused, and so are `pty: true` calls unless the process carries `PI_NO_PTY=1`; use `async: true` (with `timeout: 0`) and poll. **Contract for item 100 (C1–C6)** is PLAN.md § "3. Contract for item 100 (C1–C6)". It holds only for sessions where the switch is on. C4 is a subset: a name absent from `cert.env` is not exported, and brush withholds reserved names and `GIT_ALTERNATE_OBJECT_DIRECTORIES`. **Behaviour change where the switch is on.** Named calls lose broker readiness, restart and `proc://` stdin. `pty: true` calls are refused unless the process carries `PI_NO_PTY=1`, which the launchers no longer set. With the fence off (`gates.fence.enabled: false`) every bash call is refused, naming the two fixes: turn the fence on, or `as2 clean-shell off`. `.envrc` no longer loads. A session started from a terminal whose `SHELL` is bash is refused every call, with the fix named. A hook in the launch env or a dotenv file, or a drifted profile key, stops all bash in that session until fixed. Where the switch is off, nothing changes. **Proofs.** The session regression runs with the switch on in its scratch profile; `gates/test/shell-start-session-switch.test.ts` shows switch off reproduces the old behaviour (named and pty calls run) and that one running session follows `as2 clean-shell off` and `as2 clean-shell <wl>` on its next call. Every `omp` the proofs spawn runs under a 90 s hard kill and a 2 GiB footprint cap (`gates/test/rss-watchdog.ts`). PLAN § 5 item 3 (the live proof and guard-replay corpus run) is dropped. **Rollout (order matters).** Merge, fast-forward the main checkout, then run `as2 install`: extensions load in place from the main checkout, but `config.yml` is the installed copy, and the install brings `gates.cleanShell: "off"`. Restart the orchestrator through `bin/as2` and relaunch lanes; running sessions keep the old gates until restarted. Then `as2 clean-shell <one wl-id>`, and widen to `as2 clean-shell all` only after that lane has run normally. `as2 clean-shell off` turns it off everywhere on the next call. A re-install resets the switch to `"off"`.
