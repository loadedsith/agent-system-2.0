**Built on branch `wl/wl-mv718fxhwwcn40`.** Workload `wl-mv718fxhwwcn40` (production stakes, plan revision 6 at `~/agent-scratch/agent-system-2.0/wl-mv718fxhwwcn40/PLAN.md`, approved by Jo). Until now, any change on main to a file the test-exec bundle is built from (for example `surface/src/types.ts`) made the full-suite runner's preflight refuse every run with "re-run install/as2test-setup.sh". Each merge of that kind therefore cost Jo a manual sudo run before any lane could get a green.

**What changed.**
- A root-owned helper, `/usr/local/libexec/as2test/refresh`, rendered by `renderRefreshHelper` in `surface/src/as2test.ts` (CLI `render-refresh`). It takes no arguments (any argument exits 64) and reads nothing from its caller: it re-execs under `env -i`, so no environment, cwd, checkout or branch reaches it. It fetches `main` from the fixed URL `AS2TEST_ORIGIN` (`https://github.com/thewolff/agent-system-2.0.git`) into a root-only mirror under `/usr/local/libexec/as2test/refresh.d`, builds `test-exec.js` and `exec` as `nobody`, checks the outputs on root-only staged copies, installs them root:wheel 0755, and writes `SOURCE` last. It prints `refreshed <old12>..<new12>` or `current <sha12>`. Exit codes: 0 ok, 64 usage, 69 lock, 70 fetch, 71 build or check, 72 install, 77 not root.
- A second sudoers line in the as2test drop-in: `<jo> ALL=(root) NOPASSWD: /usr/local/libexec/as2test/refresh ""`. The trailing `""` allows the helper only with no arguments.
- `installDecision` gives each failure a kind, checked in this order: `install` (account, SOURCE, owners and modes, the `bun` and `refresh` hashes; only setup fixes these), `file-drift` (installed `exec` or `test-exec.js` missing or not matching SOURCE), `input-drift` (a bundle input in the runner's checkout differs).
- The runner's preflight now checks the install before the first sweep. On `file-drift` or `input-drift` it runs `sudo -n <libexec>/refresh` once, then checks again once. A refreshed run carries on and its summary says `refreshed <old12>..<new12>`. Two typed errors end a run without a question to Jo: `bundle-refresh-failed` (the helper exited non-zero, or exited 0 but a file still does not match SOURCE) and `checkout-drift` (the runner's checkout is not at origin/main, which no refresh can fix).
- `install/as2test-setup.sh` installs the helper, `refresh.d` and both sudoers lines; it no longer builds `test-exec.js` from its own checkout. It refuses a dirty checkout or an `origin` other than `thewolff/agent-system-2.0`, and its preview shows the checkout's HEAD, the helper's full text and sha-256, and both sudoers lines. Its last step runs the helper through the new rule. `--undo` is unchanged and removes the helper with the rest of libexec.
- New pinned gate cases in `gates/test/as2test-refresh-pins.test.ts`: every `sudo` form of the helper or the wrapper stays refused at row 6, so a lane can never call the helper itself.

**Jo's one-time step.** With his main checkout clean, Jo runs `bash install/as2test-setup.sh` once, either from the PR branch's worktree (`/Users/jowolff/code/agent-system-2.0-lanes/wl-mv718fxhwwcn40`) before the merge or from his main checkout after it, and answers `y` to the preview. The last step runs `sudo -n /usr/local/libexec/as2test/refresh` through the new rule, which proves the rule and the root path and rebuilds the bundle from origin/main. This is his last manual run for drift. After it he runs setup again only for an install-kind error or to install a newer bun or helper; `USER-GUIDE.md` § "Who does what" has the details.

**Live acceptance.** The first full-suite run after the merge, on the follow-up PR that sets this item's `status:` and `pr:`, runs from Jo's pulled main checkout, whose bundle inputs changed in the merge. It therefore meets real drift. Its `test-run:` ledger entry must show `refreshed <old12>..<new12>` in its preflight line, end green, and raise no question to Jo. A `bundle-refresh-failed` or `checkout-drift` there fails the acceptance.

**Rollback.** Revert the PR, then run `install/as2test-setup.sh` once from main, which puts back the one-line drop-in and a bundle built by setup. Or run `bash install/as2test-setup.sh --undo`, which removes the drop-in and all of `/usr/local/libexec/as2test`, the helper included.
