**Built on branch `wl/wl-mv5qdfvv82ivwg`, PR #104.** Workload `wl-mv5qdfvv82ivwg` (production stakes, plan revision 2 at `~/agent-scratch/agent-system-2.0/wl-mv5qdfvv82ivwg/PLAN.md`, approved by Jo). Item 24's starter admits only a PR on a branch the workload is bound to: `wl/<wl>`, or a branch a holder pushed to past row 8 (`push-dest:`). Jo forbade pushing to the Plumb branches for `wl-mv5o6dxc009tz4`, so its ten `plumb/*` PRs could never run: `lane_full_test { pr: 79 }` → exit 2, "PR #79's head branch plumb/lab-budget is not one this workload is bound to". **The word:** `test-pr <wl-…> <N> [<N> …]` at the surface (`surface/src/input.ts`): the workload id is always named, never inferred; numbers are positive whole numbers separated by spaces and/or commas, deduplicated in Jo's order, at most 50; the line is a command at any length, never a numbered-batch piece, and reads the same in a paste. It is refused with the reason, writing nothing, when the workload is not open, is the standing workload, or no number or a bad number is given. Applied in one transaction: Jo's instruction on the workload (author `jo`, channel `surface`), body `test-pr <wl> <N…>`, then the surface's `test-pr: <N…> <instruction id>` naming it. Bindings accumulate; there is no unbind word, and a binding ends with its workload. No `gh` call at bind time: a number that is not a PR, or a PR in another state, is refused by the runner at start. **The reader:** `test-pr:` is a reserved control prefix whose only writer is the surface (`WRITERS`, `surface/src/launch.ts`); `boundPrs` honours an entry only when the instruction it names is on the entry's workload, kind `instruction`, author `jo`, written by the surface, with the body exactly `test-pr <wl> <the entry's numbers>` (the shape of the `superseded:` reader on PR #101, `wl/wl-mv5i3lulwwbbi8`). `prAdmissible` (`surface/src/test-run.ts`) still refuses a non-`OPEN` PR and a fork first and unconditionally, then admits a head branch in the bound branches or a number in `boundPrs`, then requires a full head sha; nothing after admission changes (reservation, `test-requested:`, fetched-sha check, `headNow` re-check, `decideRun`). The starter's line gains ` bound-by <instruction id>` when only the binding admitted the PR, so every such run is traceable to its instruction row; the `test-requested:` body is unchanged. **What stays refused:** an unbound PR on any branch; a closed or merged PR even when bound; a fork PR even when bound; a PR Jo did not name while another is bound; a binding on another workload; another repo's PR (the number is read with `gh pr view <N> -R <the workload's served repo>`). **How strong the binding is:** a lane's tools stamp its own id and refuse a body opening with a reserved prefix, the writer filter drops a `test-pr:` from anyone but the surface, the entry binds only through Jo's surface instruction with the same words, and the orchestrator's recorded instructions (`Jo: "…" — reading: …`) never equal them. **Open door, not closed here:** all of as2 runs as Jo's uid and a lane's eval runs in the lane's own OMP process, so eval code that imports the ledger module can call `recordInstruction` and `recordEntry` with `by: "orchestrator-surface"`, `author: "jo"` (the module stores the caller's stamp; item 65's family). The binding is therefore as strong as every other Jo-only control line today (`plan: approved`, Jo's `ceiling:` raise, the stakes flip, `superseded:`) and no stronger; closing it needs a process or uid boundary, or a gate on eval imports of the ledger module, across every Jo-only row. That is reported to Jo as its own gates/ workload. A forged binding would buy a test run of a same-repo open PR in the isolated `_as2test` runner, recorded on the forging lane's own workload, with no push, merge or change to the PR. **Tests:** `surface/test/test-run.test.ts` (`prAdmissible`, `boundPrs`), `surface/test/test-runner.test.ts` ("start: which PRs run"; the pre-fail case "a Jo-bound plumb PR is admitted" fails on `origin/main` with exit `refused` and no `test-requested:`), `surface/test/input.test.ts` (the word), `surface/test/launch.test.ts` and `surface/test/lane-tools.test.ts` (reserved, the surface's alone). **First use** once merged and the surface restarted: `test-pr wl-mv5o6dxc009tz4 79 70 73 76 94 95 68 75 72 74`.
